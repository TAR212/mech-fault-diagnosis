## 1. 一句话说清

这是一个**从零手写的滚动轴承故障诊断教学项目**：用物理机理合成振动信号 → 做时域/频域/包络谱分析 →
训练一个 1D-CNN 做「正常 / 故障」二分类，**全程只依赖 numpy 与 matplotlib**。

### 它是什么

- 一个**端到端可复现**的最小完整流水线：数据生成 → 信号分析 → 深度学习分类 → 可视化 → 自检
- 一份**讲清原理**的教材：每个物理量、每个算子、每个设计取舍都有出处和理由
- 一个**可验证**的工程样板：固定种子可逐位复现，29 项自检覆盖契约、物理正确性、梯度正确性

### 它不是什么（**请先读这段**）

| 容易误以为 | 实际 |
|---|---|
| 一个能在真实工业现场部署的诊断系统 | ❌ 它用**仿真信号**训练，见 §7 |
| 一个「深度学习框架」或算法库 | ❌ 它是一次具体应用，`nn1d/` 只是为教学手写的极简实现 |
| 一个性能优化的方案（准确率 1.0 很厉害） | ❌ 1.0 是**合成数据太易分**的必然结果，不是能力证明 |
| 一个需要 GPU / PyTorch 的项目 | ❌ 纯 CPU、纯 NumPy，在笔记本上 5 分钟跑完 |

## 2. 要解决什么问题

**滚动轴承**是旋转机械最易失效的部件之一。它的典型失效模式是：滚道或滚动体上出现局部损伤（点蚀、剥落），
每转一圈、每过一个滚动体，损伤点都会被**撞击**一次，产生周期性的**冲击脉冲**——
激起轴承座和传感器的高频**共振**，形成一串幅值衰减的振荡。

**诊断的核心难点**：早期损伤的冲击能量很弱，且完全淹没在强大的转频振动与噪声里。
直接看时域波形往往看不出异常，直接看频谱也只见转频与噪声底座。
**工程上的解法**是先解调、再看冲击的重复频率，因为损伤的「指纹」不在幅值而在**周期**。

本项目把这个物理过程完整地建模、复现、并验证诊断判据是否成立。

## 3. 物理原理

### 3.1 信号模型

**正常信号**：转频 1x 为主成分（50 Hz，对应 3000 rpm，幅值 1.0），
再叠加幅度随机的 2x / 3x 谐波（`preprocess1.py` 中 `HARMONIC_AMP_RANGE` 取 0.02–0.12，
模拟机械松动、对中不良等次要成分），以及高斯白噪声（`AMP_NOISE = 0.15`）：

```
x_normal(t) = Σ_h A_h·sin(2π·h·f_rot·t + φ_h) + noise(t)     h ∈ {1, 2, 3}
```

其中 `A_1 = A_rot = 1.0`（转子不平衡/偏心引起的主振动），`A_2, A_3 ~ U(0.02, 0.12)`，
`φ_h` 每条信号独立随机。代码见 `preprocess1.py:100-114` 的 `synth_normal()`。

**故障信号**：在上述正常成分之上，叠加以 `T = 1/BPFO` 为间隔的**衰减振荡冲击串**。
每击激起一个共振频率为 `f_n` 的衰减振荡，`f_n` 在 500–4000 Hz 内随机
（**条内固定、条间随机** —— 即一条信号内的所有冲击共用同一个 `f_n`）：

```
x_fault(t) = x_normal(t) + Σ_k A_imp·exp(-α·(t - t_k))·sin(2π·f_n·(t - t_k))·u(t - t_k) + noise(t)
```

其中 `t_k = τ_0 + k·T` 是第 k 次冲击的发生时刻（`τ_0` 为初相位，含 ±5% 周期的抖动），
`A_imp = AMP_IMPULSE = 2.0`，`α = IMPULSE_DECAY = 800 1/s`（即衰减时间常数 `τ = 1/α = 1.25 ms`），
`u(·)` 为单位阶跃。代码见 `preprocess1.py:117-159` 的 `synth_fault()`。

其中 `T = 1/BPFO` 是冲击间隔，`τ` 是衰减时间常数，`f_n` 是共振频率。

### 3.2 为什么是 BPFO

轴承特征频率由**几何参数**决定，`config.py:64-69` 定义轴承几何（8 个滚动体、滚动体直径 7.94 mm、节圆直径 38.5 mm、接触角 0°），`config.py:71-76` 用标准公式计算：

| 频率 | 含义 | 本项目取值 |
|---|---|---|
| **BPFO** | 外圈故障特征频率 | **158.7532 Hz** |
| BPFI | 内圈故障特征频率 | 241.2468 Hz |
| BSF | 滚动体故障特征频率 | 116.0658 Hz |
| FTF | 保持架故障特征频率 | 19.8442 Hz |

本项目模拟**外圈故障**，所以冲击重复频率 = BPFO。
更关键的是**冲击间隔** `1/BPFO = 6.2991 ms` —— 这是后面所有诊断判据的「标尺」。

> 一个反直觉但重要的细节：**共振频率 `f_n` 在单条信号内固定，但逐条随机**。
> 现实里不同轴承/安装条件下的共振频带确实不同，所以不能把某个数字写死；
> 建模时必须让共振仅在**单条信号内**保持一致，否则包络自相关检不出周期性。

### 3.3 诊断判据的层次

从「看幅值」到「看周期」，判据的鲁棒性逐级提升：

| 层次 | 指标 | 本项目实测（正常 → 故障） | 问题 |
|---|---|---|---|
| 时域幅值 | RMS | 0.727 → 0.852（1.17×） | 差异小，受工况影响大 |
| 时域形状 | 峭度 | 1.665 → 2.658（1.60×） | 对冲击敏感，但噪声大时退化 |
| 频谱 | BPFO 谐波功率 | 抬升 **+25.8 / +25.7 / +29.3 dB** | 需先知道 BPFO |
| **包络谱** | BPFO 谐波功率 | 抬升 **+33.8 / +33.0 / +30.2 dB** | ✅ **最锐利** |
| **周期自相关** | 包络自相关系数 | 0.015 → **0.976** | ✅ **最可靠（抗幅值波动）** |

**最关键的一课**（项目里踩过真实的坑）：
故障包络是「稠密周期性梳状」，受转频调制 + 相位抖动。
**任何纯幅值阈值都会失效** —— 实测全局 MAD 阈值算出来比包络最大值还高（`max/thr ≈ 0.92 < 1`），
换阈值形式解决不了。真正管用的是**周期性**：包络自相关在 `1/BPFO` 处的主峰，
正常只有 0.015，故障高达 0.976。所以最终实现采用**三级判据**：
带通滤波挡掉转频 → 周期性门控 → 再叠 MAD 阈值拾峰。

## 4. 三步流水线

```
preprocess1.py  →  fft1.py  →  cnn1.py
   数据生成          信号分析       模型训练与评估
```

### 第 1 步 · `preprocess1.py` —— 数据集生成

**做什么**：合成 800 条 3 秒信号（正常 400 + 故障 400）→ 滑动窗口切片 → 打标签 → 存盘。

| 关键参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 12000 Hz | 覆盖到 4 kHz 共振带 |
| 单条时长 | 3 s（36000 点） | 足够容纳约 476 次冲击 |
| 窗口 | 1024 点（≈85.3 ms） | 约容纳 13 次冲击 |
| 滑动步长 | 256 点（75% 重叠） | **这个重叠是双刃剑，见 §5.1** |
| 每条窗口数 | (36000−1024)/256 + 1 = **137** | |
| **总样本数** | 800 × 137 = **109600** | |

**产物**：`data/clean_signal1.npy` —— 一个 `np.save` 落盘的**字典**，
含 `X (109600,1024) float32`、`y (109600,) int64`、`seg_id (109600,) int64`、
`raw (800,36000) float32`、`meta`（自描述元数据）。

> **为什么用 `np.save` 存字典而不是 `npz`**：单文件、无压缩、加载快，
> 且 `meta` 能带上生成参数，让数据集**自描述**、可审计。

**这一小步也是整个项目最贵的一步**：脚本会花约 10 秒做**4 项自检**，
包括用包络自相关反推冲击间隔（断言 `freq_rel_err_max < 0.005`，即误差 **< 0.5%**）、
用「劈半谱峰一致率」证明共振频率在条内固定。

### 第 2 步 · `fft1.py` —— 时域 + 频域分析

**做什么**：加载数据集，取正常/故障各 20 条样本，做四件事：

1. **时域波形对比** —— 标出冲击时刻、测 RMS/峰值/峭度/裕度
2. **频谱对比** —— FFT 后标出 BPFO 1x/2x/3x 与转频参考线，量化 dB 抬升
3. **包络谱对比** —— 解调后看 BPFO 谱线，验证「冲击重复频率」
4. **冲击自动检出** —— 用 §3.3 的三级判据，统计检出数与间隔误差

**产物**：`figures/fig_time_domain.png`、`figures/fig_spectrum.png`、`figures/fig_envelope_spectrum.png`、`analysis_report.md`

**最有说服力的两个数字**：

- 冲击检出 **477 个 / 3 s**，理论 **476.25 个** —— 间隔中位数 6.333 ms、均值 6.300±0.064 ms，
  相对理论值 `1/BPFO = 6.299 ms` 误差仅 **+0.54%**
- 正常样本 **0 误报** —— 靠的不是阈值，是周期性门控（见 §3.3）

### 第 3 步 · `cnn1.py` —— 1D-CNN 训练与评估

**做什么**：加载 npy → 按 segment 划分 → 标准化 → 手写 CNN 训练 → 评估出图 → 落盘指标。

**网络结构**（`nn1d/model.py`，纯 NumPy 手写）：

```
输入 (batch, 1, 1024)
  → Conv1d(1→16, k=9)   → BatchNorm → ReLU → MaxPool(2)
  → Conv1d(16→32, k=7)  → BatchNorm → ReLU → MaxPool(2)
  → Conv1d(32→64, k=5)  → BatchNorm → ReLU → MaxPool(2)
  → GlobalAvgPool       → Dropout(0.3)
  → Linear(64→64)       → ReLU → Dropout(0.3)
  → Linear(64→2)        → Softmax
```

**参数量 18594**（运行时、理论手算、参数清单求和，三者断言相等）。

**产物**：`results/metrics.json` + 4 张图（Loss 曲线、Accuracy 曲线、混淆矩阵、单样本预测演示）。

**实测结果**：

| 指标 | 值 |
|---|---|
| 训练/测试划分 | 87680 窗 / 640 条 · 21920 窗 / 160 条 |
| 测试准确率 | **1.0000** |
| 混淆矩阵 | `[[10549, 0], [0, 11371]]` |

## 5. 关键技术决策（以及为什么）

这一节是这个项目**最有价值的部分** —— 每个决策都对应一个真实的坑。

### 5.1 防数据泄漏：按 segment 划分，不按窗口划分

**坑**：滑窗重叠 75%，相邻窗口共享 768 个采样点，几乎是同一段信号。
如果按**窗口**随机划分训练/测试集，测试集里会有大量「训练集的近邻」，
模型只要记住它们就能拿到接近 100% 的**虚高准确率** —— 而这个数字毫无意义。

**解法**：`dataio.split_by_segment()` 先按 `seg_id` 把**原始信号**划分开，
再各自取窗口。实测训练 640 条 / 测试 160 条，`seg_id` 交集为 **0**。

> 这是整个项目**最重要的正确性红线**。判别方法很简单：
> `np.intersect1d(np.unique(seg[train]), np.unique(seg[test])).size == 0`。

### 5.2 标准化也必须防泄漏

**坑**：用全量数据算均值/标准差，等于把测试集信息泄漏进训练。

**解法**：`fit_normalizer()` 只从**训练集**统计 `mean=0.0131 / std=0.7910`，
`apply_normalizer()` 把它应用到测试集。`results/metrics.json` 里专门有
`normalization.source = "train_only"` 字段自证。

### 5.3 用 GlobalAvgPool 而不是 Flatten

**坑**：若在第 3 个池化层后接 `Flatten`，张量是 `(64, 123)`（64 通道 × 123 个时间步，不是 128），
展平成 **7872** 维，接 `Linear(7872→64)` 直接产生 **503,872** 个参数 ——
占全模型 **518,306** 个参数的 **97.2%**，严重过拟合，且对冲击的**相位平移**极其敏感（冲击晚 10 ms 就面目全非）。

**解法**：`GlobalAvgPool` 把每个通道在时间维上求平均 → (64,)。
参数量压到 **18594**，且**天然抗相位平移**（平均与位置无关）。
对「周期性冲击」这种平移不变的判据，这是更正确的归纳偏置。

### 5.4 纯 NumPy 手写，不用 PyTorch

**理由**（按重要性排序）：

1. **环境现实**：目标环境无 torch，且网络受限不能安装
2. **教学价值**：手写意味着每个算子的**前向与反向公式都可见** ——
   `nn1d/layers.py` 里 `Conv1d.backward` 用 `col2im` 做转置卷积、
   `MaxPool1d.backward` 要处理 argmax 路由，这些在框架里都被藏起来了
3. **可信度**：反向传播的正确性由**数值梯度**独立验证（中心差分 vs 解析梯度，
   最大相对误差 ~1e-11），不依赖「框架应该是对的」

> 这个选择**顺带暴露了一个真 bug**：`BatchNorm1d` 的 `dx` 第三项漏乘 `istd`。
> 原测试只查了 `dW`/`db`，所以漏网；补上对 `dx` 的数值梯度校验后立刻抓出来。
> **如果直接用框架，这个 bug 根本不会存在，但也学不到「怎么发现它」。**

### 5.5 固定种子，逐位可复现

`config.SEED = 42` 派生出多路独立种子（划分 42、初始化 43、打乱 44、Dropout 1042、演示抽样 49），
避免「用同一个随机流做多件事」导致的隐性相关。

**验证方式**：两次独立整跑，`train_loss[0] = 0.04422906536411675`、
`test_loss[-1] = 4.81475850047389e-07`、`lr[1] = 0.00291` **逐位一致**。
只有墙钟耗时浮动（机器负载导致，属正常）。

## 7. 已知局限（**请务必读**）

诚实披露边界，比夸大成果更重要。

### 7.1 数据是合成的 —— 这是最大的局限

准确率 **1.0 是预期结果**，因为类间差异是由物理公式造出来的、干净且明显。
**它证明的是「流水线端到端正确」，不是「模型在真实工业数据上有效」。**

真实场景的差距包括：变转速/变载荷、多故障耦合、传感器安装差异、
环境噪声与其它部件干扰、数据标注本身的不确定性。
**任何把这里的 1.0 当作性能承诺的解读都是错的。**

### 7.2 训练轮次是「部分轮」

为把 canonical 命令压进 20 分钟，`cnn1.py` 默认 `--steps-per-epoch 90`
（每轮只看 5760 个窗口，完整轮需 1370 步 / 87680 窗）。

**含义**：横轴的「1 epoch」**不等于**扫完一遍训练集 ——
所以「第 2 轮就收敛」比真正的完整训练出现得更早。
严格收敛分析请用 `--full-epoch`（本机约 212 s/轮）。

这一取舍已在 CLI help、运行时打印、`results/metrics.json` 的 `training_scale` 与本文中**如实披露**。

### 7.3 部分超参未做交叉验证

学习率、批大小、通道数、Dropout 都取的是经验值，**没有做网格搜索或交叉验证**。
在这个合成数据集上它们都够用，但不代表是泛化最优。

### 7.4 早停用测试集监控（教学简化）

严格做法是另留**验证集**。本项目为简化，早停直接看测试集准确率，
这会让测试集不再是「完全未知」的 —— 在这个场景下影响极小（第 1 轮就 1.0），
但作为方法论这是**不规范的**，代码里已明确标注。

### 7.5 只做二分类，且只模拟外圈故障

没有覆盖内圈（BPFI）、滚动体（BSF）、保持架（FTF）故障，
也没有做故障程度分级（早期/中期/晚期）。多故障耦合、程度回归都是未做的。

### 7.6 没有实时性 / 在线推理验证

只在离线批量数据上做了评估，没有测单窗口推理延迟、内存占用、流式处理能力。
真实部署还需要考虑模型量化、边缘设备适配。

### 7.7 其余局限

`cnn1.py` 在脚本末尾会打印**完整的 7 条已知局限**（见 `cnn1.py:656-672`）。
除上面展开的几条外，还包括：滑动窗口来自同一条信号、窗口间高度相关，
样本量被高估（统计置信区间比看起来更宽）；归一化统计量是全局单通道标量，
真实数据若各通道量纲差异大应改为逐通道统计；网络是朴素全卷积 + 全连接，
没有残差、注意力或频域特征融合。**建议直接跑一次看原话**，不要只依赖本文件的转述。

## 9. 为什么这个项目值得看

- **物理与算法是打通的**：从轴承几何算 BPFO，到冲击间隔 6.299 ms 的验证，
  到「为什么纯幅值阈值必然失效」，到 CNN 的归纳偏置 —— 每一环都能追到物理或数学依据
- **错误是真实且公开的**：包络自相关一开始误差 4.27%（载波周期干扰，改为先解调再自相关后降到 0.084%）；
  MAD 阈值 0 检出的真实根因；BatchNorm 反向漏乘 `istd` 的真 bug；
  Windows GBK 编码让 `cnn1.py` 在训练前就崩溃的缺陷。**这些都写进了文档，没有藏。**
- **可验证**：29 项自检 + 一键验收 + 固定种子逐位复现 + 数值梯度独立校验
- **零重型依赖**：只需 numpy 与 matplotlib，5 分钟跑完全流程
